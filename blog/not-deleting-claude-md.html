I'm Not Deleting My CLAUDE.md

Boris Cherny says delete your CLAUDE.md. The argument is that detailed context files constrain the agent — that a fresh model does better exploring than following your notes. I read the thread. Right now, I don't agree.

TON App Is Not a 5-Minute Problem

TON App is one of the hardest things to get right and one of the easiest to lose. I've spent years watching which phrasings land, which ones feel off, which edge cases break the voice.

That's not knowledge you can rediscover by poking at the codebase for a few minutes. It's accumulated observation.

A fresh agent walking into the project doesn't have any of that. It has the code, and it has its training. It does not have the years of this wording tested badly, or users read this as aggressive, or we tried this tone and it killed the onboarding. If you delete the file that holds that, you're betting the agent re-derives it.

Maybe it does. Maybe it doesn't. Maybe it finds a version that's close enough. Maybe it finds one that's confidently wrong.

Context Is a Head Start, Not a Cage

The stronger version of the delete-it argument is that context files become stale, contradictory, or actively misleading — and that's real. A CLAUDE.md that hasn't been touched in a year is worse than none.

But the fix is to maintain it, not to delete it.

For any product with real complexity, a fresh agent benefits from a compressed map of what matters: the tone, the constraints, the things that look like bugs but aren't, the things that look fine but aren't. Without it, the agent has to search — and search time is unpredictable. It might find the context fast. It might wander. It might never find the specific thing that took you three releases to learn.

The Actual Disagreement

I'm not saying context files are always good. I'm saying the complexity of a real product — the kind where tone and edge cases are load-bearing — is exactly the case where throwing away accumulated context is the expensive move.

A toy project? Delete it, who cares. A product you've been tuning for years? The file is the years.
